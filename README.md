# 三笙 · 商品开品分析报告引擎 V9.2.5

V9.2.5 是“大图大字决策报告”最终版：老板先看结论，专业用户再看图片证据。大图讲事实，大字讲判断，短句讲动作。

## 最终报告结构

1. 老板速览：为什么能卖 / 值得继承 / 下一款优先
2. 下一款方向：证据驱动优化 / 反馈驱动升级 / 探索性方向
3. 标题表达：已表达 / 建议强化
4. 主图在卖什么：完整图片 + 图片信息标签 + 1条动作
5. 详情页证明什么：代表图 + 图片信息标签 + 1条动作
6. SKU怎么选：SKU图 + 选择维度与顺序
7. 消费者实际感受到什么：买家秀 + 聚合体验信号

## V9.2.5 关键变化

- Prompt 从“解释图片”改为“提炼图片上的商业信息”。
- 主图/详情新增 `visualSignals`，优先输出图片可核验的卖点与参数标签。
- 同一结论默认只展示一次，详细推理留在 evidenceDetail。
- 主图 × 详情 × 评论承接矩阵默认折叠。
- 商品价值不再单独重复一章，吸收到老板速览。
- 新品方案改为横向决策卡，只保留为什么做 / 产品动作 / 页面动作，并标记来源等级。
- 图片统一 `object-fit: contain`，封面、主图、详情、SKU、买家秀、方案参考图均优先完整展示，不裁切商品信息。
- SKU图片数量继续与SKU结构数量分离。
- 保留 V9.2.3 已修复的图片 HTML 标签、图片缓存与旧采集格式兼容能力。

详细规则见 `REPORT_OUTPUT_STANDARD_V9.2.5.md`、`PROMPT_ENGINEERING_V9.2.5.md` 与 `CHANGELOG_V9.2.5.md`。

## 集成约定（V9.2.5）

- `server/prompt_templates.py` 提供提示词模板注册表与商品变量说明。业务代码传入结构化变量（商品、参数、图片、评论、问答、程序统计、证据账本），不再自行拼接上下文。
- 报告数据保存为 `/reports/<taskId>.json`；页面使用独立的 `server/report.html` + `server/report.js` 通过 `data` 参数加载 JSON。可直接把这两个静态文件部署到其它服务端，UI 与后端数据接口解耦。
